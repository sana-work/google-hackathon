🟡 CONFLICT 3: Synchronous REST Chain Violates ADR-018
Type: Architecture Pattern · Source: Section 4.3 "API Design" of PRD
🟡 NEEDS CHANGE
📋 PRD Proposes
Analytics service calls DataViz API synchronously on every user request, with a 5-second timeout. Response is blocking.
⚖️ Enterprise Rule Violated
ADR-018 (Async-First Architecture): Inter-service and third-party communication must use Pub/Sub event messaging. Synchronous REST chains banned for non-critical paths after Payment Outage 2024-07.
📎 Evidence Source
ADR_018_Async_Communication.txt → Status: ACCEPTED (2024-08-12)
🔗 Post-Mortem Reference
Post_Mortem_Payment_2024_07.txt: "Root cause — synchronous REST chain to analytics service caused cascading timeout. Outage duration: 4h 12min. Revenue impact: $847K."
✅ Required Fix: Redesign analytics data flow to use Pub/Sub. Dashboard updates become eventually consistent (acceptable for analytics). Analytics failures no longer impact user-facing response latency.
🟣 CONFLICT 4: PII Logging Risk in Proposed Code
Type: Code Pattern · Source: Appendix B "Sample API Code" of PRD
🟣 ADVISORY
📋 Code Proposes
Sample code logs full request payload including customer_email and customer_id to application logs for debugging.
⚖️ Enterprise Rule
Global Security Policy v4: PII fields (email, phone, ID numbers) must be masked in all logs. Regex-based PII detection must run before any log write.
📎 Evidence Source
Global_Security_Policy_v4.txt → Section 7.3 "Log Sanitization Requirements"
🔗 Historical Context
Post_Mortem_PII_Leak_2025_01.txt: Same pattern — unmasked email in logs led to GDPR breach notification. Incident cost: €142,000 in regulatory response.
✅ Required Fix: Replace logger.info(request.payload) with PII-masked logging utility: logger.info(pii_mask(request.payload)). Ensure pii_mask() is imported from the enterprise security SDK.
